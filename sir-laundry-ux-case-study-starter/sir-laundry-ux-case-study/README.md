# Sir Laundry — UX Case Study

A campus laundry management experience designed to reduce uncertainty before students travel to the laundry service.

> **Core design question:** Can I go? When can I go? What is happening? What will it cost?

## Project overview
- **Project:** Sir Laundry
- **Type:** HCI / UX design project
- **Platform:** Mobile-first prototype
- **Focus:** Availability, timings, laundry status, order submission, tracking and estimated cost
- **Process:** Research → Define → Information Architecture → Prioritisation → Wireframes → Prototype → Usability Testing → Iteration
- **Author:** Shreya Kirdat

## Problem statement
Students using a campus laundry service may not know whether the service is available before travelling there. Uncertainty about availability and timings can result in unnecessary trips and inconvenience. Sir Laundry explores how clear service information and a simple task flow can help students make more informed decisions.

## Goals
1. Make availability and operating timings easy to find.
2. Communicate service and order states clearly.
3. Allow users to select multiple wash types with independent quantities.
4. Show estimated cost before submission.
5. Support understandable payment and order-tracking flows.
6. Design for alternate states, including temporary closure, loading and errors.

## Research summary
### Persona validation
Six students were involved in the earlier persona-validation stage: Asmi, Tanuja, Elizabeth, Mileesha, Sahin and Laxmi. This explored assumptions about laundry frequency, availability and trip uncertainty. The core problem was supported, while some solution assumptions—such as WhatsApp being a core feature—were challenged.

### Information Architecture
Open card sorting informed IA V1. Tree testing highlighted confusion around Laundry Availability versus Laundry Status, and the grouping of Services, Products and Pricing. IA V2 clarified status/availability, service-related information, payment information and personal laundry activity.

### Prototype usability testing
Five students provided feedback:
- Asmi: requested multiple wash-type choices.
- Adavay: requested multiple wash-type choices.
- Kunj: suggested keeping bottom navigation visible.
- Neermay: requested light and dark modes.
- Leo: suggested a more compact layout.

Design responses included Regular, Delicate and Heavy wash options with independent quantities, fixed bottom navigation on secondary screens, light/night mode and reduced unnecessary spacing.

### Peer benchmarking
- **GatePack — Anshul:** package status, location, verification and handover.
- **Campus Connect — Laxmi:** project, skills, matches and collaboration.
- **SportSync — Tanuja:** equipment availability, details, borrowing and activity.

**Key learning:** Information Architecture should follow the user's primary goal.

## Core experience
`Check Availability → View Timings → Check Status → Estimate Cost`

The broader laundry flow supports `Submit Laundry → Track Order → Pay`.

## Prototype states
- Availability: Open, Temporarily Closed, Closed for Today, Loading and Error
- Laundry order: In Process and Completed
- Payment: Pending and Paid
- Wash types: Regular, Delicate and Heavy
- Payment methods: UPI and Cash at Counter
